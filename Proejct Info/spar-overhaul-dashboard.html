Previous approach · event-analogue-heavy
  • Three fixed historical analogues injected into every agent prompt (Kuwait 1990, Crimea 2014, Iraq 2003)
  • All five agents saw identical anchor events → groupthink risk
  • System asked "which past wars look similar?" not "which channels activate?"
  • Round 2: silent JSON dump of Round 1 — agents could not see each other's live responses
  • analogue_assessment in JSON schema anchored agents to one war story
  • No Layer 0 control node — context was static in master_context.txt
  • Weak for novel scenarios with no close historical match
New approach · transmission-channel-first
  • 13 hardcoded transmission channels with explainable scoring formula (deterministic Python)
  • Per-channel evidence retrieval — Kuwait data may appear under Energy channel, not as the whole story
  • Agent-specific evidence packets routed by domain (Political gets sanctions + GPR; Economic gets Fed + oil)
  • Round 2: live sequential debate — each agent reads full transcript and responds by name
  • channel_assessment replaces analogue_assessment in JSON schema
  • Layer 0 runs before debate: Regime → Parser → Prioritizer → Evidence → Router
  • Designed for novel shocks — channels repeat even when events are unique
Execution flow

The new 4-phase SPAR pipeline

Implemented in spar_layer0.py + spar.py inside Quorum-CLI.

L0
Phase 1 · Layer 0

Channel Prioritization & Evidence Routing

Deterministic Python — no extra LLM calls. Scores 12 channels, retrieves per-channel evidence, builds agent-specific packets. Displayed in terminal before debate starts.

R1
Phase 2 · Round 1

Independent Domain Analysis (JSON)

Five specialists produce structured forecasts blind to each other. Each receives routed Layer 0 evidence + master regime context. Output: direction, magnitudes, channels, confidence.

R2
Phase 3 · Round 2 · NEW

Live Sequential Debate (Prose)

Agents speak in turn. Each sees the full growing transcript — Round 1 summaries plus every prior Round 2 speech. Must name another agent, agree/disagree with evidence, speak in prose.

MOD
Phase 4 · Moderator

Synthesis + Plausibility

Moderator receives Layer 0 state, Round 1 JSON, and full live debate transcript. Produces consensus scenario + minority dissent with channel-based plausibility scoring.

Layer 0 · Formal model

Mathematical formulations

Every channel activation score is computed deterministically in Python — no LLM involved. Weights sum to 100%. Scores map to priority tiers, which set evidence retrieval budgets.

Master activation score Step 0.4

Sc = 100 × ( 0.30·Ec + 0.25·Mc + 0.20·Rc + 0.15·Vc + 0.10·Zc ) where c ∈ {1…13} channels, each component ∈ [0, 1]
SymbolComponentWeightWhat it measures
EcEvent match30%Keyword overlap between shock text and channel activation keywords (invasion, oil, sanctions…)
McMechanism match25%Overlap with economic mechanism keywords (risk premium, supply shock, tightening…)
RcRegime relevance20%How current macro regime (inflation, liquidity, VIX) amplifies this channel
VcEvidence availability15%1.0 if curated evidence exists in corpus; 0.3 if not
ZcSector materiality10%Keyword overlap with sector ETFs / asset classes (XLE, XLK, XLY…)

Keyword score function sub-routine

K(text, keywords) = min(1, hits / max(3, |keywords| × 0.25)) hits = count of keywords found as substrings in text (lowercased)

Used for Ec, Mc, and Zc. Requires at least 3 keyword hits (or 25% of keyword set) to reach full score of 1.0.

Regime relevance Rc conditional

Rinflation = 0.95 if regime.inflation contains "high"
Rmonetary = 0.90 if regime.liquidity contains "tight"
Rrelief = 0.85 if regime.volatility contains "elevated"
Rgpr = 0.80 for geopolitical_risk_premium (default)
Rother = 0.7 × K(regime, mechanismc) else

Priority tier mapping Step 0.5

TierScore rangeRetrieval budgetAgent weight
PRIMARYSc ≥ 756 evidence itemsHeavy — drives forecast
SECONDARY50 ≤ Sc < 753 evidence itemsModifier — adjusts magnitude

Pilot calibration floor Ukraine only

Sc = max(Scraw, Bc) if "invasion" ∈ shock ∨ "ukraine" ∈ shock, apply floor Bc from pilot table

Temporary pilot hack — ensures known-primary channels for the Ukraine benchmark. For new events (cyber, OPEC cut, Fed crisis), only the raw formula runs — scores change completely.

Design philosophy

Hardcoded channels vs event-based activation

This is the most important distinction. The channel list is fixed; which channels activate is fully event-driven.

✦ Fixed ontology (intentional)

The 13 transmission channels are hardcoded because they represent reusable financial mechanisms — the same pathways appear across different geopolitical events:

  • Kuwait 1990 and Russia 2022 both activate Energy Shock
  • Cyber attacks activate Cyber/Operational — wars do not
  • OPEC cuts activate Energy without activating Geopolitical Risk Premium

This mirrors macro finance: factor models use fixed factors (value, momentum, size) — you don't invent new factors per stock. Events select which factors load.

✦ Event-driven activation (dynamic)

What changes per event is computed, not hardcoded:

  • Scores Sc — from shock text + regime via keyword matching
  • Priority tiers — PRIMARY/SECONDARY/WATCHLIST/INACTIVE per event
  • Evidence retrieved — budget 0/1/3/6 based on score
  • Agent packets — different specialists get different channel subsets

Switch shock type below — watch scores reorder completely. Cyber attack → Cyber channel leads. OPEC cut → Energy leads. Fed crisis → Monetary leads.

Ukraine invasion — channel scores (formula output)

What should NOT stay hardcoded long-term: Ukraine calibration floors (Bc), curated evidence corpus (→ live FRED/GPR RAG), and possibly LLM-assisted channel discovery for novel shock types. The ontology itself should grow slowly via research, not per-event.
